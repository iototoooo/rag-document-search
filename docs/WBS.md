## 2. 差異の分析

| 観点 | 内容 |
| --- | --- |
| 短縮できた要因 | 共通仕様（型・API 契約・DB スキーマ・担当ファイル表）を先に main で確定し、3 機能を並列実装したため競合がなかった。外部サービスをすべてモック化し、待ち時間がなかった |
| 想定より時間がかかった点 | 共通仕様の設計（工程 2）。RLS・認可・出典管理の設計を先に固める必要があった |
| 計画に入っていなかった作業 | PDF の康熙部首・部首補助文字の正規化、CSV の列ずれ対応、Next.js 16 の新仕様（proxy・Cache Components）への対応、型展開エラー（TS2589）の回避 |
| 残る工程のリスク | 実 API の精度が目標未達の場合のチューニング時間（工程 9 が 1〜3 時間に伸びる可能性） |
