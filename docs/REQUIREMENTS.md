## 1. 背景と目的

- 社内規程・マニュアルが PDF で分散しており、必要な情報を探すのに時間がかかる。
- 社員が自然文で質問すると、社内文書だけを根拠に回答し、**根拠のページ（出典）を必ず示す**検索AIを提供する。
- 文書に書かれていないことは「該当する情報が見つかりません」と答え、推測で回答しない（ハルシネーション防止）。

## 2. 利用者と権限

| 役割 | できること |
| --- | --- |
| 一般利用者 | ログイン、質問、回答・出典の閲覧、出典 PDF の閲覧（閲覧権限のある文書のみ） |
| 管理者 | 利用者の追加・停止（Supabase Dashboard）、文書の取り込み・更新（取り込み CLI） |

- サインアップ（自己登録）はできない。管理者が作成・招待し、`app_users` で有効化した利用者だけが使える。
- メールドメインの一致だけでは利用を許可しない。

## 3. 対象データ

- **学習用ダミー文書のみ**（PDF 5 件・Markdown 5 件・テスト質問 12 問）。実在の社内文書は扱わない。
- 教材にある「PDF 200 件の取り込み」は **本 MVP では未実施**（5 件で検証）。
- 部署限定（`department`）・非公開（`restricted`）の文書は、権限チェックの実装・検証が完了するまで利用対象にしない。

## 4. 機能要件

| ID | 要件 | 実装 | 検証状況 |
| --- | --- | --- | --- |

| FR-02 | 見出し・段落を考慮してチャンク分割し、ファイル名・ページ・チャンク ID を保持 | `chunker.ts` | ローカル ✅ |
| FR-03 | OpenAI `text-embedding-3-small`（1536 次元）でベクトル化し pgvector に保存 | `pipeline.ts`, マイグレーション | モック ✅ / 実 API ⏳ |
| FR-04 | 同じ文書の再取り込みで重複登録しない | ハッシュ判定 + 置換 RPC | ローカル ✅ / 実 DB ⏳ |
| FR-05 | 質問を Embedding し、類似チャンクを検索（しきい値・件数は設定可能） | `src/lib/search/` | モック ✅ / 実 DB ⏳ |
| FR-06 | Claude で検索結果だけを根拠に回答し、ファイル名・ページの出典を付ける | `src/lib/answer/` | モック ✅ / 実 API ⏳ |
| FR-07 | 根拠がない場合は「該当する情報が見つかりません」と返す | `answer-service.ts` | モック ✅ / 実 API ⏳ |

| FR-09 | 日本語チャット画面（入力・回答・ローディング・エラー・出典） | `src/components/chat/` | ビルド ✅ / ブラウザ ⏳ |
| FR-10 | 出典クリックで、権限確認のうえ該当 PDF のページを開く | `/api/documents/[id]/file` | ローカル ✅ / 実環境 ⏳ |

| FR-12 | 精度検証（正答率・検索ヒット率・出典正確性・応答時間）を実行できる | `npm run eval` | モック ✅ / 実 API ⏳ |

## 5. 非機能要件

| ID | 区分 | 要件 | 目標値 | 状況 |
| --- | --- | --- | --- | --- |
| NFR-01 | 精度 | テスト質問 12 問の正答率 | **80% 以上** | ✅ **100%（12/12）**（2026-11-23・実 API 1 回。**学習用の配布資料 5 文書・12 問での実測**。公開リポジトリの架空データや他の文書で同じ結果を保証するものではない） |
| NFR-02 | 性能 | 1 質問あたりの応答時間 | **5 秒以内**（p95） | ⚠ **未達**（p95 7.7 秒。11 問は 2.7 秒以内、1 問のみ 7.7 秒。再測定待ち） |

| NFR-05 | セキュリティ | 閲覧権限のない文書の本文・出典・件数・存在が漏れない | 漏えいゼロ | ✅ 実 DB（T-2・T-3、31/31） |
| NFR-06 | セキュリティ | service_role キー・API キーをブラウザに公開しない | — | コード確認 ✅ |
| NFR-07 | プライバシー | 質問文・文書本文・秘密情報をログに出さない | — | テスト ✅ |
| NFR-08 | 費用 | 意図しない高額モデル・自動フォールバック・過剰な再試行を防ぐ | — | 設定 ✅ |
| NFR-09 | 利用環境 | PC・スマートフォンのブラウザで利用できる | — | PC ブラウザ ✅ / スマートフォン実機 ⏳ |
| NFR-10 | 地域 | データは Supabase 東京リージョンに保存 | — | ✅ 東京（利用者の報告）。Vercel の関数も東京（`hnd1`）に設定 |

## 6. 対象外（Phase 1 では実施しない）

- Word / Confluence など PDF 以外の取り込み（Markdown は取り込み処理のみ対応、CLI では未使用）
- 部署別アクセス制御の運用（スキーマのみ用意。ポリシーは未許可）
- Slack 連携、管理画面、差分更新の自動化
- OCR（画像のみの PDF）
- SOC2 等の認証取得・規格への完全準拠の保証

これらは [Phase 2 提案書](./PHASE2_PROPOSAL.md) で扱う。

## 7. 前提・制約

- 技術: Next.js 16 + TypeScript、Supabase（PostgreSQL + pgvector + Auth + Storage）、OpenAI Embeddings、Claude API。
- 外部 API に文書本文・質問が送信される。実在文書を扱う前に、各社のデータ取り扱い条件を確認すること。
- 料金・モデル提供状況は変動するため、利用前に各社の最新情報を確認すること。
