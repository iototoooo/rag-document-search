# Phase 2 提案書・概算見積もり

| 項目 | 内容 |
| --- | --- |
| 対象 | 社内文書検索AI（RAG）Phase 2 |
| 前提 | Phase 1 の実環境検証（正答率 80% 以上・応答時間 5 秒以内）の完了 |
| 見積もりの位置づけ | **参考値**に基づく概算。要件確定後に再見積もりする |
| 作成日 | 2026-11-22 |

## 1. Phase 1 の到達点（重複計上しないための整理）

| 領域 | Phase 1 で実装済み | Phase 2 で追加するもの |
| --- | --- | --- |
| 取り込み | PDF のページ抽出・正規化・チャンク分割・Embedding、内容ハッシュによる同一文書のスキップと置き換え、手動 CLI | Word / Confluence、差分検出の自動化、削除の同期、古い原本の自動削除 |
| 権限 | 認証・`app_users` による利用許可、RLS、`visibility`・`department` 列、`app_users.departments` 列、漏えい防止のテスト | 部署別ポリシーの有効化・管理・実 DB での検証 |
| UI | 日本語チャット、出典表示・PDF 表示、スマホ対応 | 管理画面、Slack からの質問 |
| 運用 | CLI・SQL による手動運用手順 | 画面からの運用、監査ログ |

## 2. 提案項目と概算

| # | 項目 | 内容 | 概算費用 | 工数 |
| --- | --- | --- | --- | --- |
| 1 | Word / Confluence 対応 | `.docx` のテキスト・見出し抽出、Confluence API からのページ取得（見出し・URL を出典として保持）、取り込み CLI への統合 | 15 万円 | 3 人日 |
| 2 | 部署別アクセス制御の拡充 | `department` 文書の RLS ポリシー追加（`app_users.departments` と照合）、部署割り当ての管理、HNSW と RLS の組み合わせでの検索漏れ対策、権限ごとの実 DB テスト | 20 万円 | 4 人日 |
| 3 | Slack 連携 | Slack アプリ（スラッシュコマンド / メンション）から質問、Slack ユーザーと `app_users` の対応付け、出典リンク付き返信 | 15 万円 | 3 人日 |
| 4 | 差分更新パイプライン | 文書フォルダ（共有ドライブ等）の変更検出と定期実行、削除の同期、古い原本の自動削除、取り込み履歴 | 20 万円 | 4 人日 |
| 5 | 管理画面 | 利用者の追加・停止、文書一覧・公開範囲の変更・再取り込み、取り込み履歴・利用状況の表示（管理者ロールで保護） | 25 万円 | 5 人日 |
| | **合計** | | **95 万円** | **19 人日** |

- 各項目は Phase 1 実装済みの部分（上表）を含めずに見積もっている。たとえば #2 はスキーマ・列・テストの土台があるため、ポリシーと運用・検証が中心。#4 は「同一内容のスキップと置き換え」は実装済みで、自動検出・削除同期・定期実行が対象。
- 金額は参考値。実案件では要件・既存環境・テスト範囲により増減する。

## 3. 推奨する進め方

1. **先行（必須）**: Phase 1 の実環境検証と運用開始（本提案の前提）
2. **優先度 高**: #2 部署別アクセス制御（実文書を扱う前提条件）→ #4 差分更新（運用負荷の削減）
3. **優先度 中**: #5 管理画面（運用者が SQL を使わずに済む）
4. **要望に応じて**: #1 Word / Confluence、#3 Slack 連携

## 4. 見積もりに含まないもの（別途相談）

- 本番環境の運用費用（Supabase / Vercel の有料プラン、API 利用料）
- 実在文書の取り込み作業・文書の整備（OCR を含む）
- SSO（SAML / Entra ID 等）連携、MFA の導入
- 監査ログ・ログ保管基盤、SOC2 等の認証取得支援
- 200 件規模以上の文書での性能・精度チューニング
